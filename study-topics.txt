Killing Field 프로젝트로 공부하면 좋은 내용 정리
작성 기준: 현재 프로젝트 구조와 실제 구현 흐름

이 프로젝트는 단순한 WinForms 게임이 아니라, 직접 만든 2D/2.5D 엔진, 레이캐스팅 렌더링, D3D11 백엔드,
로그라이크 진행, 카드 보상, 적 AI, 보스 패턴, 저장소, 테스트까지 들어간 학습용으로 매우 좋은 코드베이스다.
아래 순서대로 보면 "게임이 어떻게 한 프레임씩 돌아가는지"부터 "컨텐츠와 밸런스를 어떻게 확장하는지"까지 자연스럽게 연결된다.

공부 목표:
- .sln, .csproj, 프로젝트 참조 구조 이해
- namespace, partial class, property, enum, struct 사용법 익히기
- 코드가 Engine / Game / Form으로 나뉘는 이유 이해

중점 파일:

- Engine/My2DEngine.Engine.csproj
- Game/My2DEngine.Game.csproj

볼 포인트:

- GameLogic, MapManager, EnemyManager처럼 partial class로 큰 클래스를 나눈 방식

작은 실습:

- 밸런스 스냅샷을 CSV로 저장해 변경 전후를 비교하기
- 런 리플레이나 디버그 시드 고정 기능을 만들어 밸런스 테스트를 재현 가능하게 하기
- GameConfig 상수를 카테고리별 클래스로 나누거나 설정 파일로 이동하기
- UI 입력 처리와 게임 입력 처리를 더 명확한 상태 머신으로 분리하기


마무리

이 프로젝트를 공부할 때 가장 좋은 방식은 "기능 하나를 정하고 끝까지 추적하는 것"이다.
예를 들어 '독 안개 방'을 고르면 방 템플릿, 방 활성화, 타이머, 피해 적용, 흡혈 감소, HUD 오버레이까지 따라가면 된다.
'신규 적'을 고르면 카탈로그, 스폰, AI, 이미지, 렌더링, 처치 보상까지 이어진다.

즉, 파일을 하나씩 외우기보다 기능 단위로 경로를 추적하는 식으로 공부하면 이 코드베이스에서 훨씬 많은 것을 배울 수 있다.
