# game-like-roadmap

현재 구현된 레이캐스트 FPS 로그라이크를 더 명확한 게임 경험으로 다듬기 위한 작업 플랜.

## 현재 게임 형태

프로젝트는 이미 엔진 데모를 넘어선 게임 구조를 갖고 있다.

- WinForms 호스트 기반의 `640x360` 내부 해상도 렌더링
- Doom식 레이캐스트 월드와 스프라이트 적/무기/HUD
- 메뉴, 모드 선택, 설정, 일시정지, 기록 화면
- 플레이어 이동, 대시, 스프린트, 스팀, 무기 전환, 특수기
- 방 단위 로그라이크 진행
- 일반/정예/휴식/보스 방
- 카드 보상, 분기 선택, 영구 성장, 런 저장/이어하기
- 적 AI, 보스 패턴, BGM/SFX, SQLite 저장소

핵심 부족분은 엔진 기능보다 전투 감각, 목표 다양성, 진행 선택의 의미, 피드백 연출이다.

## 선행 정리

### 1. 전체 빌드 복구

상태: 완료.

기존에는 `dotnet build My2DEngine.sln`이 root 앱에서 리소스 충돌로 실패했다.

- `Form1.resx`
- `Form1.DebugHud.resx`
- `Form1.Input.resx`

위 파일들이 같은 출력 리소스 이름인 `My2DEngine.Form1.resources`를 만들고 있다.

작업 방향:

- partial form용 `.resx`가 실제로 필요한지 확인한다.
- 필요 없다면 프로젝트에서 제외하거나 제거한다.
- 필요하다면 `LogicalName` 또는 생성 방식을 분리한다.
- SmokeTests뿐 아니라 solution build가 통과하는 상태를 기준선으로 삼는다.

적용 결과:

- `Form1.DebugHud.resx`, `Form1.Input.resx`는 기존 `Form1.resx`와 동일한 기본 템플릿이고 별도 리소스 참조가 없다.
- 파일은 삭제하지 않고 `My2DEngine.csproj`에서 `EmbeddedResource` 대상만 제외했다.
- solution build와 smoke test가 통과한다.

완료 기준:

- `dotnet build My2DEngine.sln` 성공
- `dotnet run --project My2DEngine.SmokeTests\My2DEngine.SmokeTests.csproj` 성공

### 2. `.agent` 문서 동기화

상태: 완료.

문서 일부가 실제 코드와 어긋나 있다.

- 실제 프로젝트는 `.NET 8.0 Windows` 기반이다.
- 일부 밸런스 수치가 `GameConfig`와 다르다.
- 적 AI 상태명이 현재 코드와 다르다.
- 일부 무기 설명이 예전 이름/동작을 기준으로 남아 있다.

작업 방향:

- `CLAUDE.md`의 프로젝트 개요와 빌드 정보를 실제 `.csproj` 기준으로 수정한다.
- `player.md`, `game-logic.md`, `stage-flow.md`, `add-weapon.md`, `add-enemy.md`의 수치와 상태명을 현재 코드 기준으로 맞춘다.
- 문서는 설계 의도와 현재 구현을 구분해서 쓴다.

완료 기준:

- 새 작업자가 문서만 보고 현재 빌드/실행/핵심 구조를 틀리지 않게 파악할 수 있다.

적용 결과:

- `CLAUDE.md`의 런타임 정보를 `.NET 8.0 Windows` 기준으로 수정했다.
- 플레이어 수치, 적 AI 상태명, 적 성장률, AutoCannon/DuelBerettas 현재 동작 설명을 실제 코드 기준으로 맞췄다.
- `add-enemy.md`, `add-weapon.md`, `balance-tune.md`의 오래된 상태명/성장률/무기 설명을 정리했다.

## 1단계: 전투 체감 강화

목표는 무기와 적 처치가 더 직접적으로 느껴지게 만드는 것이다.

### AutoCannon 투사체화

상태: 완료.

`GameLogic.Projectiles`의 플레이어 로켓 생성, 이동, 벽/적 충돌, 폭발 처리가 AutoCannon 기본 발사 흐름에 연결되었다.

작업 방향:

- `AutoCannon` 발사를 즉시 타겟 폭발이 아니라 실제 투사체 생성으로 바꾼다.
- 투사체는 전방으로 이동하고 벽/적 충돌 시 폭발한다.
- 폭발 범위, 중심 피해, 감쇠 피해, 카메라 흔들림, 착탄 이펙트를 연결한다.
- 로켓 비행음/폭발음을 기존 오디오 시스템에 연결한다.

완료 기준:

- 플레이어가 발사체의 이동을 볼 수 있다.
- 벽/적 충돌 위치에서 폭발한다.
- 폭발 피해가 시각/청각 피드백과 함께 들어간다.

적용 결과:

- `FireAutoCannonShell()`이 즉시 타겟 폭발 대신 플레이어 로켓을 생성한다.
- 로켓은 플레이어 전방에서 시작해 `RocketProjectileSpeed`로 이동하고, 벽/적 충돌 또는 수명 종료 시 폭발한다.
- AutoCannon smoke test가 추가되어 발사 시 `PlayerRocket` 투사체가 생성되는지 검증한다.

### DuelBerettas 동작 정리

상태: 완료.

DuelBerettas는 빠른 홀드 연사 무기로 확정했다.

작업 방향:

- hold rapid fire 무기로 유지한다.
- 선택하지 않은 charge/release 동작의 죽은 상태와 필드를 정리한다.
- HUD, 탄약, 특수기 설명을 실제 동작에 맞춘다.

완료 기준:

- 입력 방식과 무기 설명이 일치한다.
- 사용하지 않는 charge/pending 상태가 전투 흐름을 헷갈리게 하지 않는다.

적용 결과:

- `Weapon`에서 `PendingChargeFire`, `ChargeLevel`, `IsCharging`, `StartCharge()`, `CancelCharge()`, `FireCharged()`를 제거했다.
- DuelBerettas는 `FireButtonHeld`와 `PendingShot` 반복 세팅으로만 연사한다.
- charge 전용 `GameConfig` 상수를 제거하고 문서 설명을 홀드 연사 기준으로 정리했다.

### 피격/처치 피드백

상태: 완료.

작업 방향:

- 히트마커 또는 짧은 명중 표시 추가
- 적 피격 flash/stagger 강화
- 처치 시 드롭/점수/코인 피드백 강화
- 탄약 부족, 재사용 대기, 특수기 가능 상태를 HUD에서 명확히 표시

완료 기준:

- 플레이어가 맞췄는지, 죽였는지, 왜 발사할 수 없는지 즉시 알 수 있다.

적용 결과:

- 모든 플레이어 피해 경로가 `DamageEnemy()`를 통해 명중/처치 피드백을 기록한다.
- 단발, 산탄, AutoCannon 폭발, DuelBerettas 피버 모드가 같은 히트마커 규칙을 공유한다.
- HUD 중앙 조준점 주변에 짧은 흰색 명중 마커와 붉은 처치 마커를 표시한다.
- 발사 불가 시 조준점 아래에 `NO AMMO` 또는 `READY 0.xs` 상태를 짧게 표시한다.
- 탄약/코인 드롭 발생과 Health/Stim/Ammo/Coin 획득을 오른쪽 HUD 토스트로 표시한다.
- 기존 상단 중앙의 아이템 획득/일반 방 클리어 메시지는 제거해 중복 피드백을 줄였다.
- 적은 피격 직후 짧은 `HitReactTimer` 동안 이동 속도가 둔화되고, 렌더 스케일 펄스와 강화된 hit flash로 맞는 느낌을 준다.

## 2단계: 방 목표와 진행 선택 강화

목표는 매 층이 단순 전투 반복으로 느껴지지 않게 만드는 것이다.

### 방 목표 추가

상태: 1차 완료.

현재 로그라이크 구조는 한 층에 시작실과 하나의 메인 방을 생성하고, 메인 방 클리어 후 카드/분기 흐름으로 넘어간다.

구현된 목표/위험:

- 전멸 방: 기존 방식. 모든 적 제거 시 클리어.
- 생존 방: `RoomObjectiveKind.Survive`. 제한 시간 동안 주기적으로 증원이 생성되고, 버티면 클리어되며 남은 적은 정리된다.
- 열쇠 방: `RoomObjectiveKind.KeyTarget`. 일반 적처럼 보이는 은닉 표적이 반드시 출현하고, 표적을 처치하면 클리어되며 남은 적은 정리된다. 표적은 훨씬 많은 체력을 가지며, 충분히 피해를 입거나 주변 적이 모두 정리된 뒤에만 노란 체력바로 드러난다.
- 독성 안개 방: `RoomHazardKind.ToxicMist`. 전투 중 독성 안개가 일정 주기로 플레이어에게 피해를 주고, 화면에는 녹색 안개 오버레이가 깔린다.
- 보급 부족 방: `RoomHazardKind.SupplyShortage`. 방 안 적 처치 드롭은 전부 막히고, 클리어 스탯 카드 보상 등급이 한 단계 상승한다.

완료 기준:

- 최소 2개 이상의 전투 목표가 실제 런에서 등장한다.
- 목표별 안내문, 클리어 조건, 보상 처리가 분리되어 있다.

적용 결과:

- `RoomTemplate`, `StageRoomBlueprint`, `StageRoomState`에 목표/위험 데이터를 추가했다.
- `RoomTemplateLibrary`가 일반/정예 전투방에 전멸/생존/열쇠 목표와 독성 안개/보급 부족 modifier를 무작위로 붙인다.
- 활성 방 하단 안내에는 목표와 남은 시간/남은 적/위험 modifier가 표시된다.
- 분기 카드에는 목표와 위험이 항상 표시되고, Sense는 기존처럼 적/보상 상세 공개 범위를 조절한다.
- 스모크 테스트가 생존/열쇠/독성 안개/보급 부족 템플릿 생성 여부를 검증한다.
- 열쇠 방 표적은 체력/후보 선정/드러남 조건을 스모크 테스트로 검증한다.

### 분기 선택 의미 강화

상태: 완료.

작업 방향:

- 다음 방 타입, 위험도, 예상 보상을 더 명확히 표시한다.
- Sense 영구 스탯은 더 많은 정보를 공개하는 역할로 강화한다.
- 고위험 방은 카드 등급, 코인, 무기 카드 확률과 연결한다.
- 연속 휴식방이 나오지 않도록 방 선택 풀을 제한한다.

완료 기준:

- 분기 선택이 단순 랜덤 진행이 아니라 플레이어의 판단으로 느껴진다.

적용 결과:

- 분기 카드에 목표, 위험도, 예상 보상, 변수, 적 정보, 방 규모를 분리해 표시한다.
- Sense 0은 적 정보를 숨기고, Sense 1~2는 적 종류/수량을, Sense 3 이상은 방 규모까지 보여준다.
- 보급 부족 방은 카드에 `스탯 카드 +1등급` 보상으로 표시된다.
- 현재 층이 휴식방이면 다음 분기 선택 풀에서 휴식방을 제외한다.
- 한 번의 분기 선택에서 휴식방 카드가 두 장 동시에 나오지 않도록 두 번째 선택지를 보정한다.
- 스모크 테스트가 `allowRestRoom: false`일 때 휴식방이 생성되지 않는지 검증한다.

## 3단계: 적과 보스 다양성 확장

목표는 층이 올라갈수록 encounter의 성격이 바뀌게 만드는 것이다.

### 일반 적 풀 확장

상태: 1차 완료.

현재 실제 랜덤 풀은 소수 일반 적 중심이고, 카탈로그에는 더 많은 아키타입이 정의되어 있다.

작업 방향:

- 층 구간별 적 풀을 나눈다.
- 보스 클리어 이후 새 적을 해금한다.
- 적 역할을 분리한다.
  - 압박형
  - 저격형
  - 돌진형
  - 소환/방해형
  - 지역 장악형

완료 기준:

- 초반/중반/후반의 적 구성이 다르게 느껴진다.
- 새 적은 시각적으로도 공격 방식이 구분된다.

적용 결과:

- 일반 적 풀을 보스 클리어 단계 기준으로 나눴다.
- 보스 클리어 전에는 기본 3종만 나오고, 1회 클리어 후 Blood Ghost/Beam Revenant, 2회 이상 클리어 후 Hellion이 실제 방 템플릿에 등장한다.
- 방 생성 시 역할 후보를 우선 배치해 압박형/저격형/돌진형/방해형/지역 장악형이 순수 랜덤에 묻히지 않게 했다.
- 스모크 테스트가 보스 클리어 전후 적 해금 규칙을 검증한다.
- 2차 확장으로 zombie scientist 시각 변형을 Uzi Trooper, Plasma Tech, Grenadier Scientist, Lab Butcher 아키타입으로 승격했다.
- 원거리 발사 스타일에 BurstPair와 WideFan을 추가해 단발/산탄 외의 압박 패턴을 만들었다.
- 초기 풀에는 Uzi Trooper/Lab Butcher가 섞이고, 첫 보스 이후 Plasma Tech/Grenadier Scientist가 해금된다.
- `zombie_scientist` 원본 프레임을 기반으로 Uzi Trooper, Plasma Tech, Grenadier Scientist, Lab Butcher 전용 이미지 폴더를 생성해 역할별 외형이 실제 에셋으로 구분된다.

### 보스 페이즈 강화

상태: 1차 완료.

작업 방향:

- 체력 구간별 패턴 변화
- 패턴 전조 표시 강화
- 보스방 구조물과 패턴의 상호작용 추가
- 보스 클리어 보상을 더 특별하게 구성

완료 기준:

- 보스가 체력 많은 일반 적이 아니라 고유한 전투로 느껴진다.

적용 결과:

- 보스 후보 풀을 보스 클리어 단계별로 확장해 첫 보스 이후 신규 보스가 실제 런에 등장한다.
- 신규 보스는 기존 4개 전용 패턴 계열에 매핑되어 기본 공격만 하는 보스가 되지 않게 했다.
- 보스 체력 66%/33% 기준으로 페이즈가 바뀌며, 페이즈가 올라갈수록 특수 패턴 windup/쿨다운, 탄막 수, 피해/범위, 돌진 거리가 강화된다.
- 보스 공격 전조 아우라가 페이즈에 따라 색과 강도가 바뀐다.
- 스모크 테스트가 보스 해금 풀 확장을 검증한다.

## 4단계: 성장과 보상 구조 강화

목표는 카드와 영구 성장 선택이 플레이 방식을 바꾸게 만드는 것이다.

### 카드 시너지 추가

상태: 1차 시작.

작업 방향:

- 단순 수치 카드와 규칙 변경 카드를 구분한다.
- 무기별 전용 카드 또는 태그 시너지를 추가한다.
- 같은 계열을 모으면 추가 효과가 생기는 구조를 검토한다.

예시:

- 대시 직후 첫 탄 강화
- 낮은 체력에서 연사/이동 보너스
- 특정 무기 탄환 관통/도탄
- 폭발 무기 범위 증가 대신 자가 피해 위험

적용 결과:

- 현재 카드 풀은 스탯 카드 17종과 무기 업그레이드 카드로 구성된다.
- 1차 시너지 카드로 `보호막 피해 증폭`과 `대시 후 피해`를 추가했다.
- `보호막 피해 증폭`은 보호막이 남아 있을 때만 모든 플레이어 피해를 증가시켜 보호막 회복/지연 감소 카드와 연결된다.
- `대시 후 피해`는 대시 직후 짧은 시간 동안 피해를 증가시켜 대시 쿨타임/처치 시 대시 환급 카드와 연결된다.
- 두 조건부 피해 카드는 각각 최대 +50%이며, 동시에 조건을 만족하면 가산으로 적용된다.

완료 기준:

- 카드 선택이 단순히 가장 큰 숫자를 고르는 문제가 아니게 된다.

### 영구 성장 개성 강화

작업 방향:

- Health, MoveSpeed, Sense, PistolDamage, Luck의 역할을 더 뚜렷하게 만든다.
- 일부 영구 성장에는 정보 공개, 시작 장비, 상점 가격, 보상 품질 같은 비전투 효과를 붙인다.
- 휴식방은 회복/탄약 3지선다가 아니라 Luck에 따라 현재 출현 가능한 최고 카드보다 한 등급 높은 스탯 카드 3장을 파는 카드 상점으로 운영한다.

완료 기준:

- 영구 성장 선택이 다음 런의 전략을 바꾼다.

## 5단계: 게임 흐름 마감

목표는 런 시작부터 실패/성공/재시작까지 완성된 게임처럼 보이게 하는 것이다.

상태: 1차 시작.

작업 방향:

- 사망 화면과 재시작/메뉴 복귀 흐름 정리
- 런 종료 요약 화면 추가
- 최고 기록/클리어 기록 UI 강화
- 시작 직후 기본 조작 안내를 짧게 제공
- 휴식방 카드 상점 선택 피드백 강화
- 최종층/엔딩/무한 모드 진입 흐름 검증

적용 결과:

- 사망 화면에 재시작/메인메뉴 버튼을 추가했다.
- 사망 화면에서 도달 층, 적 처치, 보스 처치, 플레이 시간을 간단 요약으로 표시한다.
- 사망 후 재시작/메뉴 이동 시 런 기록을 한 번만 저장하고 저장된 진행도는 삭제한다.

완료 기준:

- 플레이어가 외부 설명 없이 새 런을 시작하고, 죽고, 보상을 확인하고, 다시 시작할 수 있다.

## 테스트 확장 계획

기존 smoke test는 부팅과 기본 런 시작 확인에 가깝다.

추가할 테스트:

- solution build 검증
- 난이도별 런 시작과 첫 방 활성화
- 카드 보상 생성/선택/적용
- 분기 선택 후 다음 층 템플릿 반영
- 휴식방 구매/스킵
- 런 저장/이어하기
- AutoCannon 투사체 생성/충돌/폭발
- 보스방 진입과 클리어 보상

완료 기준:

- 핵심 게임 루프가 수정될 때 회귀를 빠르게 잡을 수 있다.
